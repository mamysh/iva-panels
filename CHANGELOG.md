# История изменений

## 0.3.0-rc.3

- Полный комплект интеграции: руководство автору, протокол карточек в чате и
  self-contained инструкции в поставляемом skill.
- Сквозная проверка стороннего примера отдельным процессом через общий API.
- Актуальные инструкции установки, диагностики и совместимости; старый журнал
  проверок вынесен отдельно. Новая главная и синтетическая схема возможностей.
- Исправлены метаданные forwarded в lockfile: версия 0.2.0 согласована с закреплённым архивом.
- Добавлена отдельная CI-проверка Bridge на exact Иве 0.5.7 без разрешения её lifecycle.
- Privacy-проверка истории и проверка локальных ссылок документации.
- Схема имени плагина в chat API согласована с каталогом, включая имена с точкой;
  ID действия проверяется по общему v2 контракту. Список поддерживаемых менеджеров не расширялся.
  Чистая установка остаётся отдельным этапом; stable 0.2.0 не меняется.

## 0.3.0-rc.2

- Reject expired/closed or owner-mismatched presentation retries.
- Bridge compatibility checks compare visible labels independently of rich markup.

## 0.3.0-rc.1

- Optional generic private chat-card transport for plugin-owned v2 proposals.
- Durable delivery intent, no replay, real message-bound confirmation.
- Rich field labels; no business decisions or arbitrary recipients in Panels.

## 0.2.0 — 2026-10-09

- Стабильный общий каталог плагинов, уровни связи и инструкция подключения для Ивы.
- Необязательный v2 API собственных настроек и действий плагина с превью,
  подтверждением, отменой и проверкой результата без автоматического повтора.
- Поставляемый skill, контракт, schema, helper и пример для авторов плагинов.
- Проверено взаимодействие с реальным socket-сервисом Bitrix24 0.9.0 через stock Bridge.
- Совместимый редактор принимает Bitrix24 0.9.0; карточка файлов знает правила 0.3.3.
- Владелец подтвердил навигацию и прежний lifecycle. Новый ручной v2 confirm и
  полная аварийная матрица не заявляются. Репозиторий остаётся приватным.

## 0.2.0-dev.2 — рабочая ветка

- Исправлена навигация v2 на главную страницу плагина: собственная кнопка больше не конфликтует с автоматической кнопкой Router.
- Сохранена совместимость старого редактора с Bitrix24 0.9.0-rc.2.
- Штатный Bridge проверяется с настоящим socket-сервисом Bitrix24 v2: отмена, подтверждение, повтор после restart Router и чтение той же policy старым редактором.

## 0.2.0-dev.1 — рабочая ветка

- Общая карточка для всех плагинов, явный уровень связи и инструкция подключения.
- Необязательный v2 API живых настроек и конечного набора действий через фиксированный приватный Unix socket; legacy адаптеры сохранены.
- Preview/confirm/cancel/status, durable intent, fingerprint установки, TTL и блокировка неизвестного исхода без повторного эффекта.
- Поставляемый skill для Ивы, публичный контракт/schema, helper локальных настроек и полный синтетический пример.
- Контракт прошёл Linux CI (82 теста, три stock версии), код 2afd9e4 установлен штатным обновлением Panels. Владелец подтвердил новые карточки, переходы, закрытие и обычный ответ Ивы в Telegram; stable не менялся.

## 0.1.0

Первый стабильный приватный выпуск на основе проверенного dev.13.

- Общий каталог установленных плагинов и навигация в одном Telegram-сообщении.
- Просмотр и подтверждённое изменение локальной политики Bitrix24; карточка отправки файлов.
- Общие enable/disable через закреплённый штатный менеджер, проверка всего реестра и результата.
- Совместимость кнопок с Bridge 0.4.14 и устойчивые пути MCP-служб через `current`.
- `panels.json` v1 для статических информационных страниц новых плагинов.

Проверен ручной цикл отмены, выключения, обычного ответа Ивы и включения на stock 0.4.14. Совместимость lifecycle ограничена exact 0.4.12/5cf и 0.4.14/fa558; новые версии требуют проверки. Полная матрица аварийного восстановления не подтверждена. Общий API динамических настроек ещё не реализован. Серверная установка версии 0.1.0 — отдельный этап; публичное открытие не выполняется этим выпуском.

## 0.1.0-dev.13

- Совместимость с кнопками Bridge 0.4.14: зарезервированный callback namespace, проверка envelope и ack без изменения сообщения со стороны Bridge.
- Поддержка закреплённого штатного менеджера 0.4.14 с полной сборкой и сохранением проверок всего реестра, служб и результата.
- Регрессии callback owner/chat/auth, повторов/доставки и интеграционная матрица exact stock 0.4.14.

## 0.1.0-dev.12

- Исправлены пути служб MCP при включении и выключении плагинов: они используют `current`, поэтому удаление старой сборки Ивы не ломает следующий запуск.
- Менеджер отказывает до выполнения команды, если переданный CLI относится к сборке, которая уже не является текущей.
- Добавлена регрессия со штатным генератором и записью units, переключением `current` и удалением предыдущей версии. Совместимость управления остаётся закреплена на stock 0.4.12; ядро 0.4.14 пока не поддерживается этим адаптером.

## 0.1.0-dev.11

- Проверка совместимости принимает штатный суффикс повторной сборки `~N`; версия, commit и source hashes ядра по-прежнему закреплены.
- Регрессия проверяет поколения сборки и отклоняет другую версию/commit.

## 0.1.0-dev.10

- Управление stock Ивой 0.4.12 без правок ядра: неизменённый native manager и полная сборка закреплённого текущего commit вместо небезопасного reuse.
- Проверка всего реестра, соседних служб, extension/MCP artifacts и authenticated userbot health.
- Stale изменение соседа отклоняет запуск; побочный эффект даёт uncertain с именами и блокирует дальнейшее управление.
- Регрессия настоящего stock updater воспроизводит прежний сбой и проверяет native disable/enable через новый build callback.
- Старые задания читаются; downgrade parser после создания dev.10 jobs не поддержан, route rollback сохраняет код и состояние.

## 0.1.0-dev.9

- Native CLI получает Node bin и пользовательский HOME/.local/bin в ограниченном PATH. Это позволяет штатному updater найти установленный uv и восстановить окружение Telegram userbot при смене версии Ивы.
- Регрессионный тест проверяет поиск uv в пользовательском каталоге без передачи Bot token. Session/token/config юзербота Panels не меняет.
- Выключение плагина по-прежнему завершается после сборки; отдельный userbot зависит от собственного штатного восстановления, а не только Eve health.

## 0.1.0-dev.8

- Отдельный opt-in: включение и выключение существующих доверенных плагинов через штатный CLI Ивы, включая плагины без собственного panels.json.
- Превью, подтверждение и отмена; предложение связано с версией установки, источником и состоянием реестра, действует 15 минут. Самовыключение Panels заблокировано.
- Отдельная ограниченная systemd-задача сохраняет намерение до команды. Повторы и прерванные команды не запускаются автоматически. Последний результат доступен из новой панели.
- Успех требует совпадения регистрации, состояния назначенных служб, доступности Ивы и смены версии при пересборке. Частичный результат явно остаётся неподтверждённым.
- Изолированные проверки штатного менеджера и Bridge дополнены cancel/disable/enable/replay. Live-переключение стороннего плагина требует отдельной ручной проверки; descriptor v1 остаётся информационным.

## 0.1.0-dev.7

- Автоматический каталог всех установленных плагинов, включая выключенные/недоверенные; пагинация по пять, обновление списка, стабильные адреса карточек.
- Базовые карточки с ограниченным manifest и состоянием регистрации; адаптеры/разделы не вызываются для выключенных/недоверенных.
- Общий descriptor iva-panels/v1: информационные страницы/локальные переходы через panels.json, имя/версия/links/size checks, fallback карточка при ошибке. JSON Schema, CLI и пример для авторов.
- Прежние адаптеры Битрикса и файлов сохраняются. Произвольные команды, общий settings API и lifecycle кнопки не реализованы этим этапом.

Установлен в разрешённом боевом эксперименте. CI и службы прошли проверки; ручной просмотр нового каталога ожидается.

## 0.1.0-dev.6

- Отдельная панель отправки файлов: версия/commit, правила выпуска 0.3.2 и раздел обновлений.
- Проверка публичного stable по кнопке: manifest и последний push CI закреплены на одном SHA; ограниченные ответы, общий deadline, отсутствие credentials и redirects.
- Не запускает доставку, установку или штатный updater; update offer в обычном чате сохраняется. Неизвестная версия не получает лимиты 0.3.2 как подтверждённые.

Установлен в разрешённом боевом эксперименте. CI, службы и отдельное серверное чтение/проверка GitHub прошли; ручной просмотр новой панели ожидается.

## 0.1.0-dev.5

- Явно включаемый редактор настроек Битрикса: режим работы, загрузка/удаление, поля сотрудников и email. Выбор → preview → отдельное подтверждение или отмена.
- Сохранение через существующий settings tool Bitrix24 с его revision/token/TTL/lock, без прямой записи его файлов и без действий с задачами/файлами на портале.
- Durable acting intent и восстановление чтением после неопределённого исхода; повторная доставка не повторяет подтверждение.
- Канонический путь server.mjs позволяет запускать bundle через символьные пути без пропуска его main guard.

Установлен в разрешённом боевом эксперименте. CI, сервис и проход до Ивы проверены; ручная проверка редактора ожидается. Настройки на production ради проверки не менялись.

## 0.1.0-dev.4

- Компактные rich-карточки с block buttons внутри сообщения, как в меню Ивы; явная настройка presentation, старый вид остаётся доступен.
- Красная кнопка закрытия, короткая подпись «Данные» и меньше пояснений на главной карточке Bitrix24.
- Send/edit rich проверяются отдельно; после неизвестной отправки нет автоматического fallback, который мог бы создать дубликат.

Read-only граница настроек этой версии сохраняется. Установлен в разрешённом боевом эксперименте; владелец подтвердил работу нового оформления.

## 0.1.0-dev.3

- Явно включаемое меню Bitrix24: просмотр текущих действий и данных сотрудников, проверка подключения и прав webhook в одном сообщении.
- Собственная короткая stdio MCP-сессия с фиксированными read-only вызовами; общая сессия Eve не перехватывается.
- Ошибки сведений сохраняют кнопки повторной проверки и возврата. Изменения настроек остаются в разговорном меню Битрикса.
- Scoped env Bitrix24 становится доступен панелям только при opt-in; эта граница доверия описана в SECURITY.

Установлен в разрешённом боевом эксперименте. Чтение с установленным Bitrix24, сервис и проход до Ивы проверены; ручной smoke новых разделов ожидается. Стабильный выпуск не выполнен.

# История изменений

## 0.1.0-dev.2 — Unreleased

- Исправлена потеря обычного текста в collector пачке рядом с `/panels`: собственные части отделяются от обычных, сохраняется queue receipt и пересчитывается Content-Length.
- Идемпотентность переживает regroup и сдвиг индекса после частичного ack. Dev.1 state читается, новые batch keys несовместимы с обратным запуском dev.1.
- Интеграционная проверка штатных модулей Bridge на закреплённых 0.4.11/0.4.12 с отдельным процессом собранного сервиса, busy queue, retry и restart. Telegram и Eve синтетические.
- Linux launcher выполняет Node без промежуточного fork, сохраняет kernel lock и корректно принимает SIGTERM.

В разрешённом владельцем боевом эксперименте подтверждены установка, ручные переходы в одном сообщении, обычный ответ Ивы, перезапуск и возврат исходного маршрута. Стабильный выпуск не подготовлен.

## 0.1.0-dev.1 — экспериментальный первый этап

- Начальный отдельный service plugin iva-panels; режим passthrough по умолчанию.
- Read-only карточки регистрации Bitrix24 и file-delivery, команда `/panels`, возврат, обновление и закрытие в одном сообщении.
- Persistent screen state, owner/chat/message/revision/TTL checks, delivery-only edit retry и отказ от повторной неоднозначной отправки.
- HTTP forwarding с acceptance receipt для собственных событий, воспроизводимый standalone bundle, синтетические регрессионные тесты и приватность поставки.

Не выпущен и не установлен; полный штатный Bridge, Linux service lifecycle и живой Telegram не проверены.
