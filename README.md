# iva-panels

Интерактивные панели для плагинов Ивы в Telegram: переходы по кнопкам обновляют одно сообщение, а состояние экрана сохраняется между перезапусками.

**Статус: экспериментальная разработка, 0.1.0-dev.8.** Репозиторий пока приватный. Пройден изолированный маршрут штатных модулей Bridge до собранного сервиса с синтетическим Telegram. В разрешённом владельцем боевом эксперименте проверены установка, переходы в одном сообщении, обычный ответ Ивы, перезапуск и возврат исходного маршрута. Стабильный выпуск ещё не подготовлен; границы проверки описаны в [совместимости](docs/COMPATIBILITY.md).

## Что уже работает

Команда `/panels` открывает все установленные плагины, включая выключенные и плагины без доверия. Сейчас поддержаны Bitrix24 и отправка файлов: настройки Битрикса и отдельная карточка файлового плагина с версией, правилами отправки и проверкой stable. Кнопки «Обновить сведения», «К плагинам» и «Закрыть» меняют исходное сообщение.

По умолчанию карточки показывают регистрацию плагинов. При явном включении адаптера Bitrix24 доступны текущие настройки, проверка подключения и прав webhook. При отдельном включении редактора настройки можно менять через показ изменений и подтверждение. Задачи и файлы панели не меняют. Если ответ Telegram на первоначальную отправку потерян, повторное событие не создаёт ещё одно сообщение; пользователь может открыть новую панель командой.

## Для чего развивать дальше

Общие панели могут пригодиться для настроек, списков, карточек и пошаговых форм разных интеграций. Поэтому название шире меню. Будущие адаптеры должны предоставлять собственные данные и соблюдать права своего плагина. Новый плагин автоматически получает базовую карточку, а `panels.json` добавляет информационные разделы по общему контракту v1. Произвольные динамические команды пока не подключаются. Редактирование настроек ограничено локальной политикой Bitrix24; включение и выключение плагинов подключаются отдельно.

## Начать знакомство

Для разработки нужен Node.js 24:

```sh
npm ci
npm run check
```

Поставляемый сервис уже содержит зависимости в `server.mjs`. Для исследовательского запуска и требований к закрытой конфигурации см. [SETUP](docs/SETUP.md). Переключение рабочего Bridge требует отдельной проверки совместимости и явного решения владельца установки.

## Просмотр настроек Bitrix24

В `/panels` выберите **Bitrix24**, затем **Подключение**, **Права webhook**, **Действия** или **Данные**. Разделы переключаются в одном сообщении. Панели показывают настройки, которые отдаёт установленный плагин, включая исходные настройки первого запуска. При включённом редакторе выберите нужное значение: панель покажет текущие и новые настройки, затем предложит «Подтвердить» или «Отменить». Прежнее меню Ивы тоже остаётся доступным.

Адаптер включается оператором отдельно: `bitrixReadOnly: true` в приватном конфиге. Он запускает собственную короткую MCP-сессию плагина Bitrix24 0.9.0-rc.1 и получает доступ к его приватным параметрам подключения. Границы и установка описаны в [SETUP](docs/SETUP.md) и [SECURITY](SECURITY.md). Dev.3 установлен в разрешённом боевом эксперименте: сервис и проход до Ивы проверены, ручная проверка новых разделов ожидается. Подтверждённые ранее ручные переходы относятся к dev.2.

## Вид меню

Панели поддерживают компактные rich-карточки с кнопками внутри сообщения, как меню Ивы. Оператор задаёт `"presentation": "rich"` в приватном конфиге; по умолчанию сохраняется `classic`. «Закрыть» выделено красным стилем. Для нового вида откройте свежий `/panels`; старые сообщения сами не обновляются.

## Изменение настроек

Редактор включается отдельно через `"bitrixSettings": true` и требует включённого адаптера чтения. В «Действиях» можно выбрать чтение или запись с подтверждением, разрешить загрузку и удаление. В «Данных» — выбрать поля сотрудников и email. Каждый выбор сначала показывает изменение; сохраняет его отдельная кнопка «Подтвердить». Кнопка «Отменить» сохраняет прежние значения. Запись настроек выполняет сам плагин Битрикса.

Сохранение отменяет прежнее подготовленное превью задачи. Права webhook на портале остаются прежними. Если запрос прервался, проверьте текущие настройки: панели не повторяют изменение автоматически. Dev.5 установлен в разрешённом боевом эксперименте; владелец сообщил, что меню Битрикса работает. Сохранение конкретного изменения отдельно не подтверждено. Dev.6 установлен; ручной просмотр новой панели отправки файлов отдельно не подтверждён. Dev.7 с общим каталогом установлен, ручная проверка списка ожидается. Владелец подтвердил работу rich-меню dev.4.

## Отправка файлов

В `/panels` выберите **Отправка файлов**. Карточка показывает версию установленного плагина и commit. **Правила отправки** описывают выпуск 0.3.2: один документ или группа из 2–10, до 50 МиБ на файл, только текущий личный чат владельца и файлы из `vault/attachments`. Для другой или неизвестной версии лимиты не подтверждаются автоматически. Это сведения о правилах, а не проверка реальной доставки.

**Обновления → Проверить stable** читает публичный GitHub: commit stable, manifest этого commit и последний push CI workflow `ci.yml` на том же SHA. При сетевой ошибке остаются кнопки повтора и возврата. Проверка не меняет предложение штатного обновления и не устанавливает код; источник вашей установки может быть закреплён на другом tag или ветке. Для обновления попросите Иву: «Проверь обновление плагина доставки файлов» и используйте её штатное подтверждение. Переключателей настроек у файлового плагина 0.3.2 нет.

## Новые плагины

Каталог автоматически читает регистрации Ивы и показывает пять плагинов на страницу. Для базовой карточки специальная поддержка не нужна. Кнопка «Обновить список» перечитывает установки.

Включённый и доверенный плагин может поставить `panels.json` рядом с manifest, чтобы добавить собственные информационные разделы без правки Panels. [Правила подключения, JSON Schema и пример](docs/PLUGIN_API.md) доступны автору плагина. V1 поддерживает страницы и навигацию; динамические настройки пока работают через встроенный адаптер Битрикса. При отдельном разрешении оператора доступны включение и выключение через штатный менеджер Ивы. Для этих кнопок descriptor не нужен.

## Включить или выключить плагин

В карточке выберите **Управление плагином**, затем **Выключить плагин** или **Включить плагин**. Panels сначала покажет изменение. **Отменить** оставляет состояние прежним; **Подтвердить** передаёт команду штатному менеджеру Ивы. Затем нажмите **Проверить результат**. После перезапуска можно открыть новый `/panels` → нужный плагин → Управление плагином → Последняя задача.

Функция выключена по умолчанию и требует настройки оператором. Доступны только уже установленные, доверенные плагины с закреплённой версией; выключенные тоже можно включить. Сам Panels через своё меню не выключается. Настройки и файлы не удаляются. MCP-плагин может потребовать пересборки и короткого перезапуска Ивы. Неоднозначный результат автоматически не повторяется. Подробности и возврат прежнего режима — в [SETUP](docs/SETUP.md).
