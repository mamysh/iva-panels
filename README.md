# iva-panels

Интерактивные панели для плагинов Ивы в Telegram: переходы по кнопкам обновляют одно сообщение, а состояние экрана сохраняется между перезапусками.

**Рабочая версия: 0.2.0-dev.1. Последний стабильный выпуск: 0.1.0.** Новый общий API подготовлен локально; установленный stable/dev.13 автоматически не обновляется.

В этой версии все плагины открываются через общую карточку: состояние, уровень связи и подключение к Panels. V1 означает справку и навигацию; v2 предоставляет живые настройки и действия через API самого плагина. Кнопка «Подключить к Panels» даёт готовый запрос Иве, а поставляемый skill объясняет, как подготовить поддержку. Самостоятельная работа плагина сохраняется. [Общий API и пример](docs/DYNAMIC_API.md).

**Стабильный выпуск 0.1.0:** Источник установки — ветка `stable` или неизменяемый tag `v0.1.0`. Репозиторий остаётся приватным. Подтверждены переходы в одном сообщении, отмена, выключение и обратное включение файлового плагина, сохранение Битрикса и обычный ответ Ивы на stock 0.4.14. Автоматические проверки охватывают три закреплённые версии Bridge и менеджер на поддерживаемых версиях. Границы совместимости и восстановления описаны в [COMPATIBILITY](docs/COMPATIBILITY.md).

Включение и выключение используют неизменённый штатный менеджер Ивы 0.4.12 или 0.4.14 с полной сборкой той же версии: это обходит ошибку повторного использования готового дерева. Panels проверяет весь реестр, службы, файлы сборки и юзербот. Неоднозначный результат останавливает последующие переключения до проверки оператора. Подробности — в [совместимости](docs/COMPATIBILITY.md).

После обновления Ивы до 0.4.14 откройте новый `/panels`: dev.13 использует кнопки `iva_panels:`, которые Bridge передаёт без отметок и преобразования в текст. Старые сообщения с `ipanel:` не обновляются автоматически. Поддержка управления закреплена за проверенными commit и хешами исходников менеджера.

## Что уже работает

Команда `/panels` открывает все установленные плагины, включая выключенные и плагины без доверия. Сейчас поддержаны Bitrix24 и отправка файлов: настройки Битрикса и отдельная карточка файлового плагина с версией, правилами отправки и проверкой stable. Кнопки «Обновить сведения», «К плагинам» и «Закрыть» меняют исходное сообщение.

По умолчанию карточки показывают регистрацию плагинов. При явном включении адаптера Bitrix24 доступны текущие настройки, проверка подключения и прав webhook. При отдельном включении редактора настройки можно менять через показ изменений и подтверждение. Задачи и файлы панели не меняют. Если ответ Telegram на первоначальную отправку потерян, повторное событие не создаёт ещё одно сообщение; пользователь может открыть новую панель командой.

## Для чего развивать дальше

Общие панели могут пригодиться для настроек, списков, карточек и пошаговых форм разных интеграций. Поэтому название шире меню. Будущие адаптеры должны предоставлять собственные данные и соблюдать права своего плагина. Новый плагин автоматически получает базовую карточку, а `panels.json` добавляет информационные разделы по общему контракту v1. Общий v2 API подключает конечный набор настроек и действий; он разрешается оператором отдельно. Редактирование настроек ограничено локальной политикой Bitrix24; включение и выключение плагинов подключаются отдельно.

## Просмотр настроек Bitrix24

В `/panels` выберите **Bitrix24**, затем **Подключение**, **Права webhook**, **Действия** или **Данные**. Разделы переключаются в одном сообщении. Панели показывают настройки, которые отдаёт установленный плагин, включая исходные настройки первого запуска. При включённом редакторе выберите нужное значение: панель покажет текущие и новые настройки, затем предложит «Подтвердить» или «Отменить». Прежнее меню Ивы тоже остаётся доступным.

Адаптер включается оператором отдельно: `bitrixReadOnly: true` в приватном конфиге. Он запускает собственную короткую MCP-сессию плагина Bitrix24 0.9.0-rc.1 и получает доступ к его приватным параметрам подключения. Границы и установка описаны в [SETUP](docs/SETUP.md) и [SECURITY](SECURITY.md). Dev.3 установлен в разрешённом боевом эксперименте: сервис и проход до Ивы проверены, ручная проверка новых разделов ожидается. Подтверждённые ранее ручные переходы относятся к dev.2.

## Вид меню

Панели поддерживают компактные rich-карточки с кнопками внутри сообщения, как меню Ивы. Оператор задаёт `"presentation": "rich"` в приватном конфиге; по умолчанию сохраняется `classic`. «Закрыть» выделено красным стилем. Для нового вида откройте свежий `/panels`; старые сообщения сами не обновляются.

## Изменение настроек

Редактор включается отдельно через `"bitrixSettings": true` и требует включённого адаптера чтения. В «Действиях» можно выбрать чтение или запись с подтверждением, разрешить загрузку и удаление. В «Данных» — выбрать поля сотрудников и email. Каждый выбор сначала показывает изменение; сохраняет его отдельная кнопка «Подтвердить». Кнопка «Отменить» сохраняет прежние значения. Запись настроек выполняет сам плагин Битрикса.

Сохранение отменяет прежнее подготовленное превью задачи. Права webhook на портале остаются прежними. Если запрос прервался, проверьте текущие настройки: панели не повторяют изменение автоматически. Dev.5 установлен в разрешённом боевом эксперименте; владелец сообщил, что меню Битрикса работает. Сохранение конкретного изменения отдельно не подтверждено. Dev.6 установлен; ручной просмотр новой панели отправки файлов отдельно не подтверждён. Dev.7 с общим каталогом установлен, ручная проверка списка ожидается. Владелец подтвердил работу rich-меню dev.4.

## Отправка файлов

В `/panels` выберите **Отправка файлов**. Карточка показывает версию установленного плагина и commit. **Правила отправки** описывают выпуск 0.3.2: один документ или группа из 2–10, до 50 МиБ на файл, только текущий личный чат владельца и файлы из `vault/attachments`. Для другой или неизвестной версии лимиты не подтверждаются автоматически. Это сведения о правилах, а не проверка реальной доставки.

**Обновления → Проверить stable** читает публичный GitHub: commit stable, manifest этого commit и последний push CI workflow `ci.yml` на том же SHA. При сетевой ошибке остаются кнопки повтора и возврата. Проверка не меняет предложение штатного обновления и не устанавливает код; источник вашей установки может быть закреплён на другом tag или ветке. Для обновления попросите Иву: «Проверь обновление плагина доставки файлов» и используйте её штатное подтверждение. Переключателей настроек у файлового плагина 0.3.2 нет.

## Новые плагины

Каталог автоматически читает регистрации Ивы и показывает пять плагинов на страницу. Для базовой карточки специальная поддержка не нужна. Кнопка «Обновить список» перечитывает установки.

Включённый и доверенный плагин может поставить `panels.json` рядом с manifest, чтобы добавить собственные информационные разделы без правки Panels. [Правила подключения, JSON Schema и пример](docs/PLUGIN_API.md) доступны автору плагина. V1 поддерживает страницы и навигацию; v2 добавляет динамические настройки и действия через локальный API плагина. Встроенная панель Битрикса сохранена как совместимый путь. При отдельном разрешении оператора доступны включение и выключение через штатный менеджер Ивы. Для этих кнопок descriptor не нужен.

## Включить или выключить плагин

В карточке выберите **Управление плагином**, затем **Выключить плагин** или **Включить плагин**. Panels сначала покажет изменение. **Отменить** оставляет состояние прежним; **Подтвердить** передаёт команду штатному менеджеру Ивы. Затем нажмите **Проверить результат**. После перезапуска можно открыть новый `/panels` → нужный плагин → Управление плагином → Последняя задача.

Функция выключена по умолчанию и требует настройки оператором. Доступны только уже установленные, доверенные плагины с закреплённой версией; выключенные тоже можно включить. Сам Panels через своё меню не выключается. Настройки и файлы не удаляются. MCP-плагин может потребовать пересборки и короткого перезапуска Ивы. Неоднозначный результат автоматически не повторяется. Подробности и возврат прежнего режима — в [SETUP](docs/SETUP.md).

Операторский цикл выключения и включения file-delivery проверен на dev.10/11: версия и commit ядра сохранены, Bitrix24 остался включённым, службы и юзербот прошли проверку. Для выключения результат dev.10 дополнительно сверял оператор; включение dev.11 получило подтверждение непосредственно от worker. Новый ручной цикл кнопок dev.11 и полная проверка восстановления после аварии ещё не подтверждены. Репозиторий остаётся приватным.

Dev.12 исправляет пути служб MCP после управления плагинами: следующий запуск сохраняется при удалении старой сборки Ивы. Dev.13 сохраняет это исправление и добавляет проверенную изолированными сценариями поддержку stock 0.4.14. Владелец подтвердил отмену, выключение, обычный ответ Ивы и обратное включение файлового плагина на 0.4.14; серверная сверка подтвердила результат и сохранение Битрикса.

Выключение завершается после пересборки: до результата «Штатная команда завершилась» прежняя Ива ещё может вызывать инструменты плагина. Флаг регистрации меняется раньше. Кроме того, штатный `send_file` ядра работает независимо от file-delivery: выключение плагина не запрещает всю отправку файлов.

Текущие границы автоматических, операторских и ручных проверок собраны в [COMPATIBILITY](docs/COMPATIBILITY.md). Исторические этапы описаны в [CHANGELOG](CHANGELOG.md).

## Подключение новых и существующих плагинов

Откройте карточку → **Подключить к Panels**. Она показывает, отсутствует ли описание, несовместимо ли оно, доступна ли только справка или объявлен общий API. Готовый запрос загружает у Ивы skill `iva-panels-integration`: Ива проверяет исходники плагина и готовит подключение по общему контракту. Само нажатие не правит файлы и не выдаёт доверие.

Для v2 оператор включает `dynamicPanels: true`. В карточке появится **Настройки**, **Действия плагина** или **Настройки и действия** согласно возможностям плагина; доступность проверяется при открытии. Плагин отдаёт текущее состояние и варианты выбора. Выбор показывает изменение, отдельное подтверждение сохраняет его. После сбоя остаётся проверка результата без повтора записи. Для разработки доступны [контракт, schema, helper и рабочий пример](docs/DYNAMIC_API.md). Иве поставляется та же инструкция вместе с Panels, без доступа к приватному справочнику владельца.
