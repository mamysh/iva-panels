# Совместимость и доказательства

Состояние на 7 октября 2026 года: `0.1.0-dev.2`. Проверка выполняется без настоящих Telegram updates и без обращения к рабочей установке.

## Изолированный маршрут Bridge

`scripts/check-bridge.mjs` импортирует штатные модули Ивы целиком: `processTelegramUpdate`, control dispatch, durable inbox, collector, routing, delivery и queue. Их код не извлекается и не заменяется. Исходники Ивы не патчатся. Собранный `server.mjs` запускается отдельным процессом и перезапускается с сохранёнными данными.

Границы среды: синтетические updates, HTTP Eve заглушка, Bot API заглушка через временный preload. `getUpdates` запрещён; главный polling loop и настоящий Eve/model turn не запускаются. Run status занятой/свободной Ивы устанавливается тестом. Такой тест подтверждает совместимость маршрута модулей, но не является ручным или серверным live-test.

Проверяются открытие, callback transform с исходным message ID и владельцем, edit в том же сообщении, restart и duplicate, busy queue/drain, отказ редактирования и delivery retry после restart, native Eve callback, обычный текст, reset/cancel HTTP forwarding и collector batches в обоих порядках. Также проверяется тело service unit штатного генератора Ивы. Это генерация unit, а не запуск systemd.

## Остальные границы

| Граница           | Автоматическая проверка                                                                                        | Ещё требуется                                                          |
| ----------------- | -------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| Экран и квитанции | Повторы, частичный ack/regroup, restart, потерянный send, edit retry, owner/chat/message/revision/TTL          | Аварии диска и процессы при SIGKILL                                    |
| HTTP              | Mixed batches разделяются с сохранением queue receipt; body length пересчитывается; ordinary/native forwarding | Живой Eve, реальные native menu/reset/cancel сценарии                  |
| Linux service     | CI проверяет launcher: lock второго процесса, остановка и повторный запуск                                     | Полный lifecycle install/trust/start/stop через менеджер Ивы и systemd |
| Telegram          | Targeted send/edit на HTTP заглушках                                                                           | Тестовый бот и ручные нажатия, реальные ошибки Bot API                 |
| Интеграции        | Карточки локальной регистрации                                                                                 | Реальные read-only Bitrix24/file-delivery adapters                     |

При обновлении ядра повторяйте проверку на новом exact SHA. Текущий middleware зависит от внутренних batch, callback, queue и acceptance контрактов. Бизнес-записи не поддерживаются.
