# Совместимость и доказательства

Состояние на 7 октября 2026 года: `0.1.0-dev.2`. Автоматические проверки используют синтетические updates. Отдельно выполнен разрешённый владельцем боевой эксперимент, описанный ниже.

## Изолированный маршрут Bridge

`scripts/check-bridge.mjs` импортирует штатные модули Ивы целиком: `processTelegramUpdate`, control dispatch, durable inbox, collector, routing, delivery и queue. Их код не извлекается и не заменяется. Исходники Ивы не патчатся. Собранный `server.mjs` запускается отдельным процессом и перезапускается с сохранёнными данными.

Границы среды: синтетические updates, HTTP Eve заглушка, Bot API заглушка через временный preload. `getUpdates` запрещён; главный polling loop и настоящий Eve/model turn не запускаются. Run status занятой/свободной Ивы устанавливается тестом. Такой тест подтверждает совместимость маршрута модулей, но не является ручным или серверным live-test.

Проверяются открытие, callback transform с исходным message ID и владельцем, edit в том же сообщении, restart и duplicate, busy queue/drain, отказ редактирования и delivery retry после restart, native Eve callback, обычный текст, reset/cancel HTTP forwarding и collector batches в обоих порядках. Также проверяется тело service unit штатного генератора Ивы. Это генерация unit, а не запуск systemd.

## Остальные границы

| Граница           | Автоматическая проверка                                                                                        | Ещё требуется                                                         |
| ----------------- | -------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------- |
| Экран и квитанции | Повторы, частичный ack/regroup, restart, потерянный send, edit retry, owner/chat/message/revision/TTL          | Аварии диска и процессы при SIGKILL                                   |
| HTTP              | Mixed batches разделяются с сохранением queue receipt; body length пересчитывается; ordinary/native forwarding | Реальные native menu/reset/cancel сценарии                            |
| Linux service     | CI проверяет launcher: lock второго процесса, остановка и повторный запуск                                     | Дополнительные конфигурации установки; один боевой lifecycle проверен |
| Telegram          | Targeted send/edit на HTTP заглушках                                                                           | Дополнительные реальные ошибки Bot API и busy queue                   |
| Интеграции        | Карточки локальной регистрации                                                                                 | Реальные read-only Bitrix24/file-delivery adapters                    |

При обновлении ядра повторяйте проверку на новом exact SHA. Текущий middleware зависит от внутренних batch, callback, queue и acceptance контрактов. Бизнес-записи не поддерживаются.

## Боевой эксперимент 7 октября 2026

Поставлена `0.1.0-dev.2`, точный plugin commit `6200949754800af926d0a86aadbd953deac65355`. Основа ядра — Iva 0.4.12 / `5cf8f196`; существующее локальное наложение установки сохранено. Проверка относится к этому экземпляру, а не ко всем конфигурациям Ивы.

- Штатные proposal, ручная кнопка установки владельца, trust и запуск service unit прошли. Исходники ядра и его версия не изменялись; процесс Eve не перезапускался.
- Подтверждены реальный loopback маршрут Bridge, listener и проход health-запроса до Eve.
- Владелец подтвердил ручные переходы Bitrix24 → список → отправка файлов → список → закрытие в одном сообщении. State показал закрытый экран с ревизией 5 и шесть завершённых квитанций. Это проверка карточек регистрации, а не внешних API интеграций.
- Перезапуск службы сохранил state. Возврат Bridge на исходный адрес, выключение службы и повторное подключение прошли. В скрипте подключения понадобилось ожидание HTTP listener: active в systemd ещё не означает готовый порт.
- Подготовлен локальный health watchdog с возвратом исходного маршрута после трёх отказов службы. Его наличие не гарантирует восстановление любого зависшего события.

Владелец также подтвердил обычный ответ модели через окончательный маршрут и повторное открытие `/panels` с переходом в Bitrix24 после перезапуска и обратного подключения. Сервер показал второй экран с ревизией 1 и восемь завершённых квитанций без pending доставки. Busy queue и ошибки Telegram пока проверены автоматически; искусственные отказы и нагрузки в рабочем чате не создавались. Этот эксперимент не является стабильным выпуском или разрешением публичного открытия.

## Dev.3: read-only адаптер Bitrix24

Настройки и диагностика поддерживают плагин Bitrix24 0.9.0-rc.1; целевой проверяемый код — `010193e56e595d030267a49558e7ca4ff427bbde`. Установку dev.2 и подтверждённый владельцем smoke выше не считать проверкой dev.3. Опция по умолчанию выключена. Старые экраны регистрационной карточки могут открыть новое меню при следующем обновлении сведений; формат screen state не менялся.

Автоматические проверки адаптера: отдельный реальный stdio child с синтетическим MCP, только три фиксированных tool и статические аргументы; scoped env; проекция settings/connection/scopes; enabled/trusted/opt-in; ошибка оставляет кнопки возврата. Сетевой Bitrix и живой пользователь проверяются отдельно.

Отдельная серверная read-only проверка dev.3 адаптера на установленном Bitrix24 exact `010193e`: все пять разделов успешно получены через собственные stdio-сессии, подключение и scopes проверены реальными методами плагина. Хеши settings, settings-offer и активного task draft до/после совпали (отсутствующие файлы также оставались отсутствующими). Это проверка адаптера, а не подтверждение новой установки панелей или ручных переходов.

Dev.3 установлен штатным `iva plugin update iva-panels` из локального источника с сохранённой исходной dev.2 копией. Exact код `268de82680e3d5b493c8fd03e1d3308a4a959bf1`, bundle SHA-256 `1a9c5fc8ae11a1d7101ccf5cf39cdfb1ca7ecdcbbd90e7c00e2d4e6162eedf13`. Адаптер включён приватным флагом, сервис и проксируемый Eve health отвечают; ссылка версии ядра и PID Eve сохранились. CI прошёл: 40 Linux тестов и две закреплённые проверки Bridge, включая bundled adapter с синтетической stdio-сессией. Ручная проверка новых разделов ожидается; ошибки старого watchdog проверены ранее только на dev.2.
