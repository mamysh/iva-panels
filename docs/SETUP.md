# Установка и настройка

Panels — служба Ивы на Linux. Она подключается между штатным Bridge и Eve,
использует существующего Telegram-бота и не запускает второй polling.
Подключение маршрута выполняет оператор.

> Репозиторий пока приватный. Чистая установка на новую Иву ещё не принята.
> Сначала сверьте [совместимость](COMPATIBILITY.md); для 0.5.7 управление
> enable/disable через Panels не поддерживается.

## 1. Подготовить окружение

Нужны Node.js 24, `bash`, `flock`, работающая Ива с systemd user services и доступ
к исходникам выбранного выпуска. Готовый `plugin/` содержит runtime-зависимости
в bundles; `npm ci` нужен разработчику для сборки и тестов, не самой службе.

Запишите текущую версию Ивы, адрес Eve, адрес назначения Bridge и способ вернуть
прежний маршрут. Проверьте обычный ответ бота. Сохраните приватные настройки
и согласованный резерв перед изменениями; не копируйте живую БД как готовый backup.

Выберите неизменяемый ref. Для стабильного каталога и v2 — `v0.2.0`;
для карточек в чате нужен кандидат 0.3 RC. До получения доступа к приватному Git
публичная ссылка не позволит Иве скачать плагин.

## 2. Предложить установку

В подготовленном checkout под пользователем Ивы:

```sh
iva plugin propose /path/to/iva-panels/plugin
```

Путь заменяется на абсолютный путь к выбранному пакету. Подтверждение установки
выполняется штатным способом Ивы. Не подменяйте его callback, записью в реестр
или неинтерактивным обходом доверия. Точную команду для вашей версии сверяйте
со штатной справкой `iva plugin`.

Служба требует `PLUGIN_ROOT`, `PLUGIN_DATA`, `IVA_DATA_DIR`, `IVA_SERVICE_PORT`;
их назначает менеджер Ивы. Если служба ещё не стартовала из-за отсутствия config,
подготовьте файл на следующем шаге и запустите назначенную службу повторно.
Порт 8735 в descriptor запрашиваемый: используйте реально назначенный порт.

## 3. Создать приватный config

В фактическом каталоге данных Panels создайте `config.json` с правами **0600**.
Сам каталог должен иметь права **0700** и принадлежать пользователю службы.

```json
{
  "upstream": "http://127.0.0.1:9000",
  "secret": "REPLACE_WITH_EXISTING_BRIDGE_SECRET",
  "botToken": "123:REPLACE_WITH_EXISTING_BOT_TOKEN",
  "owners": [123],
  "mode": "passthrough",
  "presentation": "rich",
  "dynamicPanels": true
}
```

Это пример с заглушками. Замените адрес Eve, общий секрет Bridge, токен текущего
бота и Telegram ID разрешённого пользователя. Не отправляйте секреты в Telegram,
Git, issue или вывод диагностики. Конфиг строгий: неизвестные поля отвергаются.

`upstream` — только исходный HTTP origin Eve на **127.0.0.1**, без пути, логина
или query. Он должен отличаться от порта Panels. В `passthrough` `/panels`
передаётся Иве; режим удобен для первоначальной проверки маршрута.

| Параметр         | По умолчанию  | Действие                                                         |
| ---------------- | ------------- | ---------------------------------------------------------------- |
| `mode`           | `passthrough` | `panels` включает обработку меню и карточек.                     |
| `presentation`   | `classic`     | `rich` включает компактные блоки; `classic` — inline-клавиатуру. |
| `dynamicPanels`  | `false`       | Разрешает v2 API включённых и доверенных плагинов.               |
| `bitrixReadOnly` | `false`       | Включает прежний адаптер чтения и диагностики Bitrix24.          |
| `bitrixSettings` | `false`       | Включает прежний редактор; требует `bitrixReadOnly`.             |
| `lifecycle`      | отсутствует   | Отдельно разрешает enable/disable только совместимого менеджера. |

Для v2 Bitrix24 прежний адаптер не обязателен. Карточки в чате создают
`PLUGIN_DATA/chat.sock` только при `mode: panels` и `dynamicPanels: true`;
запросы требуют ровно одного `owner` в конфиге.

## 4. Проверить службу и подключить маршрут

Перезапустите назначенную менеджером службу Panels и дождитесь HTTP listener.
`GET /health` на её loopback-порту показывает режим и работу listener;
этого недостаточно для проверки Telegram, Eve и внешних интеграций.

Сначала проверьте прямую связь с Eve. Затем направьте только адрес назначения
Bridge на фактический loopback-порт Panels. В исследованных версиях это
`ASSISTANT_HOST`; способ задания зависит от версии и установки Ивы.
Общий origin Eve не меняется. Плагин не выполняет это подключение автоматически.

Проверьте обычный текст через маршрут в `passthrough`. Затем задайте
`"mode": "panels"`, перезапустите Panels и откройте новый `/panels`.
Убедитесь, что список, карточки, возврат и закрытие меняют одно сообщение,
а обычные ответы Ивы и её штатные кнопки продолжают работать.

Полный перечень проверок — в [плане чистой установки](ACCEPTANCE.md).
Для rich используйте актуальный Telegram-клиент. При проблемах с видом выберите
`classic` и откройте новую панель; после неизвестной отправки переключение
способа доставки автоматически не повторяется.

## 5. Подключить плагины

Новая регистрация видна автоматически. V1 добавляет справку, v2 — настройки и
действия при наличии собственного API. Кнопка **«Подключить к Panels»** показывает
готовый запрос для skill Ивы; она не выдаёт доверие и не правит исходники.
[Интеграция](INTEGRATION.md), [карточки в чате](CHAT_CARDS.md).

Прежний Bitrix-адаптер поддерживает точные 0.9.0/rc.1/rc.2. Он читает штатный
`bitrix24-read.env` и запускает отдельную stdio-сессию. Не включайте его только
ради нового v2; [полномочия и ограничения](../SECURITY.md).

Панель file-delivery включается для доверенного работающего плагина без отдельного
флага. GitHub запрашивается только кнопкой проверки stable. Обновление выполняется
через штатный механизм Ивы.

## Дополнительно: enable/disable

Эта функция ограничена exact менеджерами **0.4.12/5cf8f196** и **0.4.14/fa558655**.
Для 0.5.7 оставьте `lifecycle` отсутствующим. Нельзя обходить проверку версии
заменой имени каталога или хеша.

```json
{ "lifecycle": { "cli": "/opt/iva/current/bin/iva.mjs" } }
```

Это фрагмент, который добавляется к существующему config; путь заменяется
фактическим штатным CLI через `current`. Нужны пользовательский systemd,
`XDG_RUNTIME_DIR` и права того же пользователя. Panels получает право только
на enable/disable уже установленных доверенных закреплённых плагинов.

Операция может пересобрать состав плагинов на том же commit ядра и кратко
перезапустить Иву. Отмена preview ничего не переключает. После подтверждения
дождитесь **«Проверить результат»**: один флаг `enabled=false` ещё не доказывает
завершение сборки. Сам Panels через себя не выключается.

Worker: одна unit `iva-panels-lifecycle.service`, `Restart=no`, предел 900 секунд;
CLI ограничен 600 секундами. Queued/running/uncertain блокируют новые команды.
Оператор сверяет unit, весь реестр, artifacts/services, текущую сборку и health
юзербота. Автоматического повтора, обратной команды или восстановления реестра нет.
Журнал ограничен 100 задачами; архивировать можно только проверенные завершённые
задачи, сохраняя незавершённые.

## Обновление и возврат

Обновление плагина — штатная операция Ивы с выбранным источником/ref, резервом
и проверкой версии после завершения. Публикация нового stable не меняет
автоматически закреплённый RC или локальный источник установленного плагина.

До downgrade проверьте отсутствие pending/acting/uncertain в screen, dynamic и
lifecycle журналах. Старые версии могут не понимать новые поля и фазы.
Безопасный первый способ восстановления связи — **вернуть маршрут Bridge прямо
к исходному Eve**, дождаться health и проверить обычный ответ. Затем можно
остановить Panels. Отдельная lifecycle-задача от этого не отменяется.

Не восстанавливайте живые очереди, offsets, настройки или registry целиком
из старого снимка ради отката интерфейса. Возврат кода не откатывает данные.
После смены версии открывайте свежий `/panels`. Подробности диагностики —
в [FAQ](FAQ.md), границы хранения — в [SECURITY](../SECURITY.md).
