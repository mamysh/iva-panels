# 0011. Прямой вход в возможности и диагностика интеграции

Принято для 0.3.0-rc.5.

Похожая кнопка может сохранить обычную задачу Ивы либо подтвердить действие
плагина. Каталог раньше начинался со сведений, затем предлагал параллельно
«Совместимую панель», «Настройки» и подключение. Собственный iva-panels также
предлагал подключить себя к себе. Это мешало понять ожидаемый результат.

Название в каталоге теперь ведёт прямо в v2, затем v1 или имеющуюся legacy-панель.
Сведения/подключение/enable-disable остаются под отдельной кнопкой «О плагине».
У оболочки свой экран состояния, без собственного v2 descriptor и второй службы.
Глобальный выход называется «К плагинам»; возврат к entry — «К разделам плагина».
Слово «обновить» не обозначает скрытый переход с текущего раздела на entry.

Явные команды `/panels NAME` и `/ panels` открывают те же экраны, без модельного
поиска веб-сайта. Обычный текст, штатные callback и tasks остаются у Ивы.
Чтение настроек при прямом входе не является согласием на действие.

Поставляемая read-only диагностика inspect.mjs проверяет регистрацию, descriptor,
доступ и read через существующий socket. Ответ содержит только состояния и следующий
шаг, без текста plugin screen, путей, токенов и бизнес-данных. Ready доказывает
только read. Диагностика не выполняет prepare/confirm/send и не меняет службу.
Она же доступна Иве без npm и приватного Git. Разработка интеграции относится
к конкретному другому плагину. Включение общего API не добавляет его в любой плагин.

Отдельный guide skill описывает поручение, текущую кнопку и подтверждение в чате.
Он не патчит системный промпт, tasks и память ядра; применяется после загрузки.
Новый общий task store и перехват обычных поручений не добавляются. Произвольный
плагин должен сам предоставить инструменты/подготовку для chat-v1; нельзя объявлять
универсальное выполнение всех действий из одного интерфейса.

Существующие screen IDs/callback guards, journals и формат данных сохраняются.
Старые карточки живут до TTL; новый интерфейс открывается новой /panels.
