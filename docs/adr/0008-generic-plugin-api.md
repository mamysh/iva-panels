# ADR 0008: необязательный общий API плагина

Принято для локальной разработки 0.2.0-dev.1.

## Причина

В 0.1.0 каталог и lifecycle уже общие, но descriptor v1 предоставляет лишь справку. Настройки Bitrix зависят от встроенного адаптера. Владелец запросил универсальные настройки и действия, явное состояние связи, требования авторам и поставляемую инструкцию для Ивы, разрабатывающей плагины.

## Решение

V2 объявляет имя/версию, entry и capabilities. Runtime соединяется только с приватным фиксированным Unix socket в данных включённого доверенного плагина. Он не запускает команды из descriptor и не подключается к единственной MCP-сессии ядра. Плагин реализует read/prepare/confirm/cancel/status; данные, бизнес-валидация, CAS и эффекты принадлежат ему. Panels обеспечивает экран, owner/message/revision, durable intent, проверку token/TTL, fingerprint и отсутствие повторного эффекта.

В каталоге всегда общая карточка. Отсутствующий, некорректный, статический и динамический контракты различимы; API объявлен не означает проверенную доступность. Инструкция подключения содержит запрос Иве и ссылается на поставляемый skill. При разработке новых плагинов он предлагает поддержку сразу; глобальный генератор ядра не модифицируется.

V1, lifecycle и legacy адаптеры сохранены. Новые плагины не требуют изменений Panels. API выключен по умолчанию, разрешается отдельным opt-in. Плагин работает без Panels.

## Последствия

Автоматически построить редактор из неизвестного config безопасно нельзя: нужна доработка автором/Ивой в собственном плагине. Кнопка подключения помогает подготовить её по контракту, но не выдаёт trust и не перезаписывает установленный код. Один Unix-пользователь — общая граница доверия. При смене версии или неизвестном исходе нужна status/операторская сверка. Поставляемый helper решает только атомарные локальные настройки; для внешних эффектов нужен собственный протокол идемпотентности.
