# ADR 0001: отдельный плагин панелей, чтение и локальный транспорт

Дата: 2026-10-07. Статус: принято для первого экспериментального этапа.

Нужны удобные экраны для нескольких плагинов с изменением одного Telegram-сообщения. Общий upstream API экранов пока не принят; доступ через отдельную MCP-сессию не даёт безопасного владения сообщением.

Выбрано имя iva-panels: оно охватывает меню, карточки, списки и мастера. Первый этап реализует persistent screen engine и чтение регистрации двух интеграций. Он не меняет бизнес-настройки и не доказывает доступность внешних сервисов.

Штатный Bridge остаётся единственным читателем updates. Loopback middleware принимает только свой namespace и передаёт прочие запросы Eve. Представления отделены от транспорта. Зависимость от внутреннего Bridge фиксируется как риск, требующий проверки каждого целевого SHA. Возможный официальный upstream API в будущем предпочтителен для замены транспорта.

Цена решения: дополнительная служба в критическом маршруте, хранение приватного Bot API токена, зависимость от очереди Bridge, ограниченные гарантии доставки и отсутствие общего адаптерного API. Поэтому рабочая установка требует отдельного end-to-end этапа, а запись — нового решения о правах и достоверности действия.

Репозиторий приватный. Будущее публичное открытие регулируется RELEASING и явным решением владельца; качество публичной поставки является частью задачи, а не завершающим косметическим действием.
