# Подключить свой плагин к Panels

Panels предоставляет общий renderer, навигацию и подтверждение. Плагин предоставляет
свои данные и операции. Новой интеграции не нужны имя в whitelist Panels,
собственный Telegram-бот или адаптер в исходниках Panels.

## Выбрать уровень

| Нужно                      | Реализация                                     | Контракт                                               |
| -------------------------- | ---------------------------------------------- | ------------------------------------------------------ |
| Только карточка в каталоге | Штатная регистрация в Иве                      | Дополнительных файлов нет.                             |
| Справка и страницы         | `panels.json` v1 рядом с manifest              | [v1](PLUGIN_API.md), [пример](../examples/notes/).     |
| Живые настройки/действия   | Descriptor v2 и `panels.sock` в данных плагина | [v2](DYNAMIC_API.md), [schema](panels-v2.schema.json). |
| Предложение прямо в чате   | V2 и обращение к `chat.sock` Panels            | [API карточек](CHAT_CARDS.md).                         |

Необязательный descriptor не должен ломать работу плагина без Panels.
Одно объявление v2 не создаёт API: служба должна реально обслуживать протокол.
Panels допускает вызовы только enabled/trusted плагина с совпадающими именем и версией.

## Новый плагин: начать с рабочего пакета

[dynamic-notes](../examples/dynamic-notes/) содержит manifest, descriptor, service
и сервер на Node.js 24 без npm-зависимостей. Он меняет одну локальную настройку
«Компактный вид» и атомарно сохраняет её с revision и квитанцией.

В checkout Panels:

```sh
node scripts/check-panel.ts examples/dynamic-notes
node --test test/integration-example.test.ts
```

Вторая команда проверяет копию пакета в отдельном процессе: каталог и API,
prepare без эффекта, отмену, подтверждение, повтор после рестарта и карточку в чате.
Telegram заменён тестовым транспортом; ядро Ивы для этого теста не требуется.

Перенесите пакет в собственный проект. Измените имя/версию согласованно в manifest,
descriptor и сервере; выберите свободный service port по правилам вашей Ивы.
Настройте validate/screen/propose и сохраните обычные инструменты плагина.
Установка службы и доверие выполняются штатным менеджером Ивы отдельно от теста.

## Существующий плагин: подключить его хранилище

1. Найдите авторитетное хранилище настроек, текущие права, блокировки и revision.
2. Добавьте descriptor v2 и обработчик HTTP POST `/panels/v1` на приватном
   `PLUGIN_DATA/panels.sock` (0600). Можно встроить его в действующий процесс.
3. Реализуйте `read`, `prepare`, `confirm`, `cancel`, `status` по [точному контракту](DYNAMIC_API.md).
4. Read читает текущее состояние. Prepare только сохраняет предложение.
   Confirm заново проверяет права, revision и TTL; изменение и receipt фиксируются вместе.
5. Сохраните один источник настроек для обычных инструментов и Panels.
   Не создавайте вторую конфигурацию с теми же полями.
6. Проверьте повторы, отмену, неизвестный исход, отключение/trust, смену версии
   и работу без Panels. Затем подключите v2 в конфиге оператора.

[Helper настроек](../plugin/skills/iva-panels-integration/resources/settings-service.mjs)
подходит, когда его файл является единственным хранилищем локальных настроек.
Для существующей БД нужен собственный обработчик или адаптация к ней.
Helper хранит актуальное предложение и последнюю терминальную квитанцию;
он не заменяет постоянный журнал внешних бизнес-операций.

## Действия и внешние эффекты

В `capabilities` можно объявить `actions` или сочетание `settings`/`actions`.
Кнопка read задаёт ограниченный `action`, prepare возвращает полное превью,
а confirm обращается к собственному безопасному пути исполнения плагина.

Для внешнего сервиса нужны durable job, проверка результата и собственная
идемпотентность. Потерянный ответ не разрешает повторить запись.
Status только сообщает известный результат. Права, бизнес-валидация и контроль
конкурентных изменений остаются у плагина. Передавать shell, MCP URL, callback ID,
Telegram recipient или секрет через descriptor запрещено.

## Подключение с помощью Ивы

Panels поставляет skill `iva-panels-integration` с контрактом, schema и примером кода.
Он доступен после установки плагина и не требует доступа к этому GitHub-репозиторию.

```text
Загрузи iva-panels-integration. Изучи мой плагин и добавь поддержку Panels v2:
текущие настройки, preview, confirm, cancel и status. Используй существующее
хранилище, сохрани обычные инструменты и добавь проверки повторов.
```

Для карточек добавьте просьбу поддержать `iva-panels/chat-v1`.
Кнопка «Как добавить настройки» в сведениях о плагине подсказывает такой запрос, но не исполняет его сама.
Skill не является глобальным патчем генератора Ивы и не гарантирует доработку
закрытого плагина без исходников. Если исходники недоступны, передайте автору
этот контракт и перечень нужных операций.

## Готовность интеграции

- Имя и версия совпадают в manifest, descriptor и RPC envelope.
- Схема и CLI принимают descriptor; секретов и реальных данных в нём нет.
- Socket принадлежит пользователю Ивы, имеет 0600 и канонический путь без symlink.
- Read/prepare/cancel не меняют рабочие настройки; confirm имеет проверяемый результат.
- Старый token, чужая revision, TTL и lost response не вызывают повторный эффект.
- Плагин продолжает работать без Panels; остальные интерфейсы видят те же настройки.
- Внешние операции имеют собственное восстановление, права и журнал.
- Руководство плагина описывает включение API, ошибки и ограничения.

## Диагностика на установленной Иве

Сначала выберите конкретный **другой плагин**. Сам iva-panels уже обслуживает
интерфейс и не требует подключения к себе.

При заданном фактическом IVA_DATA_DIR:

```sh
node "$IVA_DATA_DIR/custom/plugins/iva-panels/sh.iva/services/router/inspect.mjs" "$IVA_DATA_DIR" ИМЯ_ПЛАГИНА
```

Инструмент поставляется готовым bundle, не требует npm или приватной документации.
Он выводит только имя/версию, состояние и следующий шаг, без содержимого экранов.

| State            | Следующий шаг                                                                    |
| ---------------- | -------------------------------------------------------------------------------- |
| builtin          | У Panels уже есть собственный экран; второй API не нужен.                        |
| not-installed    | Уточнить имя в реестре Ивы.                                                      |
| paused           | Проверить включение/доверие штатным менеджером.                                  |
| missing / static | Добавить v2 в исходники выбранного плагина.                                      |
| invalid          | Сверить schema, имя и версию descriptor.                                         |
| disabled         | Проверить конфигурацию доступа Panels у оператора.                               |
| unavailable      | Проверить службу/socket и ответ протокола.                                       |
| ready            | Read работает; не создавать API заново. Остальные операции тестировать отдельно. |

`configuration: unavailable` означает, что config Panels не удалось безопасно
прочитать/разобрать: оператор проверяет его отдельно. Диагностика никогда не
включает доступ, не меняет trust, не выполняет prepare/confirm и не отправляет карточку.
