# Подключение плагина к Panels

## Что появляется автоматически

Каждая регистрация в `custom/plugins.json` появляется в каталоге, включая выключенные плагины и регистрации без доверия. Плагину не нужен специальный API для базовой карточки. Panels читает name, enabled, trusted, sha и ограниченный установленный manifest; версия и описание показываются при корректном manifest. Это состояние регистрации, а не health check процесса.

Список перечитывается при каждом действии; «Обновить список» показывает новые установки. Пять плагинов на страницу, до 1000 регистраций. Ключ карточки связан с именем, а не позицией: перестановка списка не меняет адресата старой кнопки. После удаления карточка предлагает вернуться к списку. Открытие списка не запускает код плагинов.

## Контракт v1: разделы и навигация

Положите `panels.json` в корень устанавливаемого плагина, рядом с `plugin.json`. Это обычный файл поставки, без секретов и данных пользователя. Отдельная регистрация в коде Panels не нужна. Panels прочитает его для включённого и доверенного плагина.

```json
{
  "schema": "iva-panels/v1",
  "plugin": "notes-example",
  "pluginVersion": "1.0.0",
  "entry": "home",
  "pages": [
    {
      "id": "home",
      "title": "Заметки",
      "body": "Возможности плагина заметок.",
      "rows": [[{ "label": "Подробнее", "target": "details" }]]
    },
    {
      "id": "details",
      "title": "Заметки · Подробнее",
      "body": "Справка о возможностях этого выпуска.",
      "rows": [[{ "label": "Назад", "target": "home" }]]
    }
  ]
}
```

`plugin` и `pluginVersion` должны совпадать с установленным manifest. После изменения версии обновляйте оба файла. `entry` и все targets должны ссылаться на существующую страницу этого же описания. ID уникальны: строчные латинские буквы, цифры и дефисы, до 24 символов, первый символ — буква.

Текст выводится буквально: HTML и Markdown из описания не исполняются. Panels добавляет «Обновить раздел», «О плагине» и «Закрыть»; карточка содержит возврат к списку. Навигация обновляет одно сообщение. Состояние экрана сохраняет вид и адреса кнопок, но свежая страница читается из текущего описания. После обновления/удаления описания устаревшая ссылка возвращает карточку.

Ограничения: файл до 32 КиБ, до 12 страниц; title до 80 символов, body до 1500; до пяти рядов по одной или две кнопки, label до 48. Конечная карточка после HTML escaping также должна уложиться в общий лимит сообщения. Ошибки описания не блокируют базовую карточку. Файл с несовместимой схемой, версией, неверными ссылками или лишними полями не подключается. Последний компонент пути не может быть symlink; файл должен быть обычным.

## Проверка для автора

[JSON Schema](panels.schema.json) помогает редактору. Она описывает форму; совпадение версии, уникальность страниц, ссылки и итоговый размер дополнительно проверяет CLI:

```sh
node scripts/check-panel.ts /path/to/plugin
```

В checkout Panels можно проверить готовый [пример](../examples/notes/panels.json):

```sh
node scripts/check-panel.ts examples/notes
```

Пример содержит metadata fixture и две информационные страницы; это не самостоятельный устанавливаемый плагин. Перенесите описание в собственный настоящий plugin package и согласуйте имя/версию. Пользовательские данные и секреты в `panels.json` и Git не помещаются.

## Настройки и команды

**v1 предоставляет информационные страницы и переходы.** Поля `command`, `tool`, URL, пути, shell, обработчики и произвольные callback IDs не поддерживаются и отвергаются. Descriptor не даёт полномочий выполнять код, сохранять настройки или включать/выключать плагин. Здесь нет подстановки актуальных значений конфигурации или подключения произвольного MCP endpoint.

Текущие Bitrix24 и file-delivery имеют встроенные адаптеры для существующих API и совместимости. Битрикс умеет preview/confirm/cancel через свой settings tool; доставка показывает сведения и публичный stable. Они служат примерами поведения, но их динамические возможности пока не выражаются через v1 descriptor. Их репозитории этим этапом не меняются.

Следующий контракт для динамических действий должен отдельно определить чтение состояния, подготовку изменения, подтверждение/отмену, revision/TTL, восстановление неизвестного исхода и права. Бизнес-валидация и токен предложения остаются у соответствующего плагина. Сырые MCP URLs или shell-команды из descriptor не становятся доверенными. Текст, преобразованный Bridge, не является независимым доказательством raw human tap.

Panels предоставляет общие кнопки включения и выключения через штатный менеджер Ивы; они описаны ниже и не зависят от descriptor. Установка, обновление, удаление и выдача доверия через Panels пока не реализованы. Для этих операций используйте штатный менеджер и существующие подтверждения Ивы.

## Общие кнопки управления

С dev.8 Panels может самостоятельно добавить включение/выключение через штатный менеджер, если оператор включил lifecycle opt-in. Для этого плагину не нужен descriptor: достаточно корректной существующей trusted регистрации и закреплённого SHA/digest. Descriptor v1 остаётся информационным и не объявляет команды управления или динамические настройки. Автор плагина должен корректно поддерживать штатный enable/disable Ивы; сервисы/MCP берутся из её регистрации. Сам Panels исключён из этих действий.
