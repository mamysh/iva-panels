# Выпуск и публичное открытие

## Решение владельца

Репозиторий создаётся приватным. Владелец допускает будущий публичный выпуск после успешной разработки и тщательной подготовки, с качеством оформления и проверки как у его Bitrix24 и file-delivery плагинов. Это требование действует на код, историю, документацию и страницу GitHub. Сам по себе успешный CI не разрешает публичное открытие.

**Изменение visibility на public выполняется только по отдельному явному поручению владельца после проверки условий ниже.** Приватная публикация исходников, release, серверная установка и публичное открытие — четыре разных этапа. Разрешение одного не означает разрешения остальных.

## Перед выпуском

- Версия согласована в package, lockfile, manifest, runtime и CHANGELOG; ссылка ведёт на immutable commit/tag.
- Чистый clone: `npm ci`, `npm run check`, `bash -n` launcher. Bundle воспроизводится без ручной правки, аудит зависимостей рассмотрен.
- Полный маршрут штатного Bridge на целевом exact SHA и Linux service lifecycle проверены отдельно. Telegram smoke подтверждён ручными нажатиями, restart и возвратом маршрута.
- Обычные сообщения, native callbacks, очередь, повторная доставка, неоднозначные ответы, удаление сообщения и ограничение ресурсов проверены. Ограничения указаны честно.
- README, SETUP, SECURITY, COMPATIBILITY и release notes совпадают с фактическими возможностями. Планируемые адаптеры не описаны как реализованные.
- Установка на рабочую систему требует отдельного решения владельца, резерва и проверки установленного SHA/служб.

## Перед открытием public

- Владелец просмотрел конкретный итог и явно разрешил открытие.
- Проверена вся Git-история, включая ранние commits, ветки, tags, assets и release notes: отсутствуют секреты, webhook, реальные ответы, личные пути, runtime данные и локальная память. При утечке секрет отзывается; одного удаления файла недостаточно.
- Чистый публичный clone содержит всю нужную документацию и воспроизводимую сборку. Приватные справочники не требуются внешнему пользователю.
- Оформлены About, темы, лицензия, инструкции поддержки, приватное сообщение об уязвимости, CI и актуальные пользовательские примеры. Скриншоты создаются на синтетических данных и показывают актуальный интерфейс.
- Не осталось необъяснённых failures, критичных зависимостей или временных debug обходов. Совместимость, права, rollback и известные ограничения документированы и подтверждены.
- Проведён итоговый просмотр интерфейса и документации с той же тщательностью, что у Bitrix24 и file-delivery. Несделанные обязательные пункты остаются явным блокером открытия.

До выполнения этих условий текущая версия остаётся экспериментальной. Сервис не переключает маршруты и не обновляет установку самостоятельно.
