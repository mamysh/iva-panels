# Проверка на чистой Иве

Это план отдельной приёмки, **не отметка о выполненной установке**.
Используйте изолированную Иву и отдельного тестового бота, synthetic-notes и
вымышленные данные. Рабочий чат и реальные бизнес-записи для этих проверок не нужны.

## Подготовка

Запишите exact SHA Ивы и Panels, ОС, Node, назначенные порты и units.
Сохраните baseline обычного ответа, штатных кнопок, реестра и служб.
Подготовьте возврат маршрута и согласованный backup с проверкой восстановления.
Не включайте lifecycle на неподдерживаемом менеджере.

## Сценарии

| Шаг                                       | Ожидаемый результат                                                                     |
| ----------------------------------------- | --------------------------------------------------------------------------------------- |
| Получить пакет по инструкции              | В поставке хватает документации, bundles, схем и skill; приватная память не нужна.      |
| Предложить установку и подтвердить штатно | Exact пакет установлен, служба получает штатные env/порт, секреты не выведены.          |
| Config и passthrough                      | Listener готов, обычный текст и штатные callbacks проходят к Eve.                       |
| Включить panels                           | Каталог, страницы, возврат и закрытие меняют одно сообщение.                            |
| Подключить synthetic-notes v2             | Read показывает текущее состояние; prepare/cancel его не меняют.                        |
| Confirm и повтор                          | Настройка меняется один раз, status показывает сохранённую квитанцию.                   |
| Запросить карточку прямо в чате           | Present ничего не применяет; кнопка нужного сообщения подтверждает.                     |
| Чужая/старая кнопка, TTL                  | Отказ без эффекта.                                                                      |
| Перезапуск Panels и API примера           | Настройки/журнал сохранены, callback и status не дублируют эффект.                      |
| Потерянный send/edit/confirm response     | Нет автоматического повтора записи или второй неизвестной отправки.                     |
| Занятый агент и mixed batch               | Очередь, обычный текст и собственные события сохраняют правильные receipts.             |
| Native menu/reset/cancel                  | Штатные команды продолжают работать через маршрут.                                      |
| Удалённое сообщение и предел экранов      | Ошибка видима, новые эффекты не повторяются ради доставки; FAQ помогает восстановлению. |
| Возврат маршрута                          | Bridge напрямую отвечает через Eve; Panels можно остановить.                            |
| Восстановление из резерва                 | Данные согласованы, нет двух poller/worker и повторного эффекта.                        |

Во время сценариев измеряйте RAM/CPU, размер state/журналов, рестарты и задержку
обычного ответа. Зафиксируйте ошибки и границы, не выдавая active/health за весь сценарий.
Enable/disable проверяется отдельно только на exact поддерживаемом менеджере,
с контролем всего реестра и соседних плагинов до/после.

## Результат

В отчёте разделите автоматические проверки, изолированную Linux-проверку,
реальный Telegram и восстановление. Укажите exact версии и доказательства;
пропущенный сценарий остаётся открытым. После успешного этапа обновите
[COMPATIBILITY](COMPATIBILITY.md), сохраняя фактические ограничения.
