# Установка Panels из чата Ивы

Кандидат **0.4.0-rc.1**. Нужна штатная Linux-установка Ивы **0.5.7/ae313753a1ae**
с user services systemd, Node.js24 и одним владельцем Telegram. Изолированные тесты
не заменяют приёмку на новой Иве и настоящем Telegram; этот этап ещё открыт.

## Что отправить Иве

```text
Установи Panels из https://github.com/mamysh/iva-panels.
Выбери проверенную версию 0.4.0-rc.1 и прочитай её INSTALL.md.
Проверь совместимость, покажи короткий план и предложи установку штатной кнопкой.
Ядро не меняй. Токены не показывай и не запрашивай в переписке.
```

Пользователь нажимает штатную кнопку установки Ивы. После установки служба Panels
сама читает локальные настройки, проверяет соединение и подключает маршрут.
При успехе приходит **«Panels готовы» → «Открыть панели»**. Готовность подтверждает
соединение и доставку начальной карточки; реальные действия других плагинов
проверяются отдельно.

## Инструкция для Ивы

1. Получи исходники выбранного immutable commit/tag. Не смешивай `main`, stable
   и кандидат. Не используй `curl | sh`; прочитай эту инструкцию и состав пакета.
2. Из корня полученного checkout запусти:

   ```sh
   node plugin/sh.iva/services/router/install.mjs plan
   ```

   `ready_to_propose` означает совместимый профиль. `already_installed` означает,
   что первая установка не нужна: проверь установленный status, не заменяй config.
   При ошибке остановись и объясни её; не редактируй ядро, pins, unit или реестр.

3. Покажи, что после нажатия будут созданы приватный config и собственный user
   drop-in маршрута, перезапущен только Telegram Bridge и поставлен независимый
   таймер возврата. Затем вызови **один раз**:

   ```sh
   node plugin/sh.iva/services/router/install.mjs propose
   ```

4. Дождись настоящего нажатия владельца на штатную кнопку. Не вызывай
   `install-proposal`, `add --trust`, поддельный callback или запись trust вручную.
   Пакет копирует и проверяет штатный менеджер Ивы.
5. Не меняй исходный checkout после предложения: его путь записывается как источник
   установки. `proposal_delivery_unknown` не разрешает создать вторую отправку.
6. После установки проверь `status` установленным инструментом. Если IVA_DATA_DIR
   не задан, возьми фактический каталог данных из штатной конфигурации Ивы,
   не выводя её секреты.

   ```sh
   node "$IVA_DATA_DIR/custom/plugins/iva-panels/sh.iva/services/router/install.mjs" status
   ```

`connected` — маршрут проверен; `notice: presented` — начальная карточка доставлена.
`notice: attempted/delivery_unknown` не доказывает доставку: не отправляй её заново,
предложи пользователю открыть `/panels`. `rolled_back` — прежний маршрут восстановлен;
`uncertain` — нужна сверка оператора, автоматический повтор запрещён.

## Если подключение не завершилось

При первом запуске до изменения маршрута создаётся отдельный user timer на120секунд.
Он использует сохранённую в данных копию recovery bundle и общий flock: падение
основной службы или изменение её исходника не удаляет код возврата. После рестарта
незавершённое подключение тоже восстанавливается, без повторного включения.

Изменённый оператором drop-in не удаляется. Ошибка самого восстановления оставляет
`uncertain`. Без работающего user manager/ОС таймер не гарантирует выполнение;
при следующем старте проверяется журнал. Изменения самого ядра не выполняются.

Повтор подключения — только по отдельному запросу владельца после `rolled_back`:

```sh
node "$IVA_DATA_DIR/custom/plugins/iva-panels/sh.iva/services/router/install.mjs" retry
```

Возврат прежнего маршрута по просьбе владельца, с сохранением плагина и данных:

```sh
node "$IVA_DATA_DIR/custom/plugins/iva-panels/sh.iva/services/router/install.mjs" disconnect
```

Существующий ручной config сохраняется. Мастер первой установки не мигрирует чужие
настройки и drop-in, не выполняет обновление Ивы и не включает lifecycle автоматически.
Для неизвестной версии, нескольких владельцев или собственного маршрута нужен
[операторский путь](docs/SETUP.md). Никакой второй polling-процесс не запускается.
